Unit testing, or modular testing•A check of the correctness of individual modules of the program source code, individual functions of the application or service.•This establishes whether the code is operational, whether it gives correct results with different inputs, and whether the logic matches the expected one.•An example: •Obtain the sum of two numbers•The input values required for testing are entered into the function•The unit test is passed if the expected result of the function is equal to the one actually obtained. •The metric is calculated by comparing the number of lines of code that passed the test to the total number of lines of code in the repository. •The best indicator is considered to be 80%.

Prepared by: Ravish MaqsoodAll rights reserved. No slide or part to be reproduced or publishedon any platform without permission of the owner. 
Integration Testing
•Testing the interaction of the components of the future application. •The integration of modules is checked. •These tests are more complex than unit testing, since the ability to perform sequential actions in various components is checked. •Example: The user logs in — is redirected to the main page — places an ad. That is, several modules are tested at once.

Prepared by: Ravish MaqsoodAll rights reserved. No slide or part to be reproduced or publishedon any platform without permission of the owner. 
System Testing•All components of the program are tested as a single application. •The specialist must ensure that the product correctly handles various scenarios and situations based on requirements.•This option may include testing non-functional requirements. •System testing requires considerable time, because as the product evolves, the number of possible use cases grows. •With each product update, it is necessary to check whether the previously tested functions work. This process is called regression testing. 

Prepared by: Ravish MaqsoodAll rights reserved. No slide or part to be reproduced or publishedon any platform without permission of the owner. 
Acceptance Testing•The product is tested by key specialists and customers.• •Check in real time •Ensure expectations and requirements have been met.• •Acceptance is the final stage of testing.•Minimize any bugs or defects fixing at this stage. Non-functional testing checks the application for:•performance•reliability•compatibility•security•utility•scalability

Definition
What is Risk?Project Risk is an uncertain event or condition that, if occurs, has a positive or negative effect on one or more project objectives such as scope, schedule, cost and quality.

Prepared by: Ravish MaqsoodAll rights reserved. No slide or part to be reproduced or publishedon any platform without permission of the owner. 
Risks•Risks will continue to emerge through out project lifecycle.•Risks must be monitored and managed.•Important to manage the risks to deliver the project within the expectations of contractual agreement.  •Level of acceptable level of risk exposure to be agreed and known upfront. •Contingencies are built in the cost and schedule estimates for risks.
